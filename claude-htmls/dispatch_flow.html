blackhole-py Dispatch Write Flow

Device/session initialization is separate from per-program kernel launch. Program layout produces bytes and L1 addresses; dispatch chooses how to deliver them.

Device init Program layout Common dispatch IR Slow direct writes Fast CQ path Host/sysmem messages

1. Device Startup / Runtime Init

Open device and discover usable hardware

  • Open PCIe device and bring ARC/device to usable state.
  • Read ARC telemetry pointers from SCRATCH_RAM_12/13.
  • Read enabled Tensix and GDDR bank masks.
  • Build worker core list and DRAM bank tile list.
↓

Upload worker firmware to every worker core

  • Write MMIO RISCV_DEBUG_REG_SOFT_RESET_0 = SOFT_RESET_ALL.
  • Write each firmware PT_LOAD segment into worker L1.
  • Remap firmware local-RAM segments into per-core scratch L1.
  • Write BRISC bootstrap JAL at L1 address 0x0.
  • Write GO_MSG = RUN_MSG_INIT.
  • Write NOC bank table to MEM_BANK_TO_NOC_SCRATCH.
  • Write MMIO reset PCs for NCRISC/TRISC0/TRISC1/TRISC2.
  • Write MMIO soft reset release value SOFT_RESET_BRISC_ONLY_RUN.
  • Poll one worker core until GO_MSG + 3 == RUN_MSG_DONE.
↓

If fast dispatch is enabled, initialize CQ runtime

  • Pin host sysmem for issue queue, completions, timestamps, and core timing.
  • Prefetch core L1 writes: queue read pointer, PCIe read pointer, zero prefetch queue.
  • Dispatch core L1 writes: completion pointers, event words, zero sync semaphore region.
  • Upload CQ prefetch/dispatch kernels at KERNEL_CONFIG_BASE + offset.
  • Write CQ launch message to LAUNCH.
  • Write CQ go signal to GO_MSG.

2. Optional Host Data Movement

Slow DRAM write/read path

  • Host writes DRAM pages directly through TLB windows.
  • Writes barrier flags to Dram.BARRIER_BASE.
  • Polls barrier flags for posted write completion.

Fast DRAM write/read path

  • Host copies payload into pinned sysmem.
  • Runtime launches a generated DRAM fill/drain kernel program.
  • That transfer program follows the same program dispatch path below.

3. Program Layout Contract

asm.py: Kernel

  • Owns instruction image, local data, and ABI declarations.
  • rta(lambda x, y: list[int]) produces per-core runtime args.
  • crta(...) stores common runtime args.
  • compile() returns kernel Segment(addr, data) entries.
↓

program.py: Program layout per core

  • Selects role kernels for each core: sender vs recv variants.
  • Evaluates selected kernel RTAs for that core.
  • Aggregates selected kernel CRTAs.
  • Packs RTA/CRTA blob at KERNEL_CONFIG_BASE.
  • Packs CB config at KERNEL_CONFIG_BASE + local_cb_off.
  • Places kernel text/local data at assigned KERNEL_CONFIG_BASE + text_off slots.
  • Builds launch message bytes at LAUNCH.
↓

Ideal common output

  • dict[Core, list[Segment]] where each segment is an absolute L1 address and bytes.
  • No device handle, no TLB writes, no CQ records, no firmware upload.
  • Dispatch may stamp dispatch-specific launch fields such as mode or host-assigned id.

4. Dispatch Builds a Shared Launch IR

Program segments become abstract writes

  • Write(cores, addr, data) for uniform bytes shared by many cores.
  • Write(cores, addr, list[bytes]) for same address but per-core bytes.
  • Dispatch groups identical (addr, data) pairs and forms multicast rectangles where possible.
  • Dispatch keeps per-core RTA blobs as packed per-core writes when they differ.
↓

Dispatch protocol messages around program bytes

  • Write GO_MSG = RUN_MSG_RESET_READ_PTR_FROM_HOST.
  • Write GO_MSG_INDEX = 0.
  • Write all program layout segments.
  • Emit abstract Launch(cores).

5A. Slow Dispatch Lowering

Direct TLB writes

  • For uniform Write, split target cores into multicast rectangles.
  • For each rectangle, set TLB target and write bytes directly to L1.
  • For per-core list[bytes], set TLB target per core and write its payload.
↓

Slow launch signal

  • For Launch(cores), write GO_MSG = RUN_MSG_GO to target cores.
  • Poll every launched core until GO_MSG + 3 == RUN_MSG_DONE.

5B. Fast Dispatch Lowering

CQ command generation

  • Uniform multicast writes lower to CQWritePackedLarge.
  • Same-address per-core payloads lower to CQWritePacked.
  • Optional timestamp commands are inserted before/after each program.
  • Optional core timing control writes go to TIMING_CONTROL.
↓

Host issue queue messages

  • Each CQ command is wrapped in a relay-inline record in pinned sysmem.
  • Host writes record size into the prefetch core queue slot.
  • Prefetch/dispatch firmware pulls commands from sysmem and performs device writes.
↓

Fast launch and completion

  • Launch(cores) lowers to CQSetGoSignalNocData.
  • Then CQWaitStream(DONE_STREAM, 0).
  • Then CQSendGoSignal(RUN_MSG_GO).
  • Then CQWaitStream(DONE_STREAM, len(cores)).
  • Host appends CQHostEvent(event_id) and waits for completion sysmem doorbell.
Boundary summary: device init writes firmware, bank tables, and CQ runtime state. Program layout emits kernel-launch bytes. Dispatch owns write grouping, multicast/packed-write optimization, go signaling, and completion handling.
